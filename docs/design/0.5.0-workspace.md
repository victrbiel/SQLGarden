# SQLGarden 0.5.0 — Native Workspace Redesign

## Research and priorities

These are qualitative issue reports, not a representative survey. Adapt the underlying usability problem rather than copying another application's UI.

| Source | Reported friction | SQLGarden response |
|---|---|---|
| [DBeaver #41183](https://github.com/dbeaver/dbeaver/issues/41183) | Active editor highlighting can make the current connection/tab ambiguous. | Keep server and database visible, strengthen selected-tab appearance using both shape and accent, retain a single shared session. |
| [DBeaver #23018](https://github.com/dbeaver/dbeaver/issues/23018) | Users want connection context identifiable in editor tabs. | Explicit connection identity and contextual window subtitle; no invented per-tab connections. |
| [Azure Data Studio #26425](https://github.com/microsoft/azuredatastudio/issues/26425) | Results header actions are not keyboard accessible. | Retain native buttons and grid keyboard navigation, label tab controls, expose result visibility in the menu with a shortcut. This does not claim a full accessibility audit. |
| [Microsoft SQL tools changelog](https://github.com/microsoft/azuredatastudio/blob/main/CHANGELOG.md) | Explorer expansion, results handling, and grid copying need efficient controls. | Add expand/collapse explorer actions, visible multiple-result selectors, and an editor-focused layout. |

## Native design contract

Use SwiftUI NavigationSplitView and VSplitView, AppKit's text editor/table, semantic system colors and standard controls. Minimum supported macOS remains 14. No new dependency or OS-27-only API. Preserve the user's existing language (Portuguese UI) and keep repository documentation in English.

Apple's split-view guidance: “provide multiple reveal paths (toolbar button or menu command, including keyboard shortcut).” Application: results can be shown/hidden through the toolbar and View menu (Shift-Command-R); executing a query reveals results again. A standard resizable divider separates editor and results.

Hierarchy: compact identity and connection header; searchable object explorer; identifiable query tabs; database/scope/run bar; editor; results/messages; compact session state footer. Show transaction state as the last explicit observation, not a live guarantee. SQL and results use opaque semantic text surfaces; material effects are reserved for existing system chrome. Branding is secondary to content.

## Scope and preservation

- Integrate the approved three-petal mascot and matching wordmark; prepare native icon resources from the approved raster artwork.
- Preserve selected results while switching query documents in the current window.
- Clarify whether Run executes selected SQL or the entire document.
- Provide useful disconnected/running/result empty states and accessible control names.
- Preserve original SQL execution, Unicode/GO parsing, errors, partial results, cancellation, Keychain, draft recovery, and history. No autocomplete, automatic SQL retry/COMMIT/ROLLBACK, new database mutations, or new session-per-tab behavior.
- Keep 0.4.0 and all earlier tags immutable. Develop this version on codex/sqlgarden-0.5-interface.

## Acceptance and validation

Compile the actual macOS app, run existing core/bridge and offline UI validation, inspect the actual native window at normal/minimum width and light/dark appearance, exercise result visibility and document navigation, and verify packaged resources and ad hoc signature. Real SQL Server regression requires a dedicated QA database and credentials; never use user databases for validation. Record actual results and limitations in the release notes.

References: [Apple split views](https://developer.apple.com/design/human-interface-guidelines/split-views), [toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars), [sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars).
